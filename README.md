# Style Advisor (Svelte Frontend)

Minimal, web-based outfit composer. The user selects an occasion and a person (man, woman, couple; men’s flow is the most complete currently), then picks garments and their colours/patterns. Colour, pattern, and type suggestions can be generated by a locally hosted Ollama model.

## Why I built this
I regularly have trouble matching garments to an occasion. Once I looked up the rules, it got easier — so instead of repeating that process, I turned it into an app.

## Why Ollama
Because the setup is easy and I'm lazy. Also the models run locally, so they're free. And since I'm fucking poor, that is a pretty good reason.

## AI colour/pattern suggestions (Ollama, local)
- Start Ollama on `http://localhost:11434`.
- Text model should respond to `/v1/systemone` (`choice` question type).
- OCR/vision model should respond to `/api/chat` with `images`.
- Defaults in code: `tev1:4b` for text choices, `lfm3-vl:2b` for vision.
- If Ollama is unavailable, dropdowns fall back to static colour/type/pattern lists.

## Switching to a cloud model (manual, example)
This app currently targets Ollama endpoints. To use a cloud provider (e.g., OpenAI-compatible), the common changes are:

1. **Endpoint URL**: replace `http://localhost:11434/v1/systemone` and `/api/chat` with your cloud URL.
   Example:
   ```js
   // Before (Ollama)
   const r = await fetch('http://localhost:11434/v1/systemone', { ... });

   // After (cloud)
   const r = await fetch('https://api.example.com/v1/chat/completions', {
     method: 'POST',
     headers: {
       'Content-Type': 'application/json',
       'Authorization': 'Bearer ' + import.meta.env.VITE_API_KEY
     },
     body: JSON.stringify({ model: 'gpt-4o-mini', messages: [...] })
   });
   ```

2. **Model names**: replace `tev1:4b` and `lfm3-vl:2b` with cloud model IDs.
3. **Auth**: add `Authorization: Bearer <key>` (store keys in env, never in repo).
4. **Response parsing**: adapt to provider JSON shape.
5. **Limits**: resize images and cap tokens per provider docs.

No automatic switching is implemented; these are manual edits for now.

## Garment SVGs
Place garment SVGs (400x400, centered) in `public/`. The `svgMap` in `src/GarmentCard.svelte` maps garment names to filenames. Women-specific variants use `_woman.svg` suffixes where available.

- The UI is bilingual (EN/PL); use the EN/PL toggle in the header.
- OCR results are verified by the user before saving; images are not persisted.

## Where the rules / data live
- `src/data/rules.js`: occasion/garment guidance and rule text passed to Ollama.
  - `GENDER_STYLING`: short gender-specific constraint appended to every Ollama suggestion request.
  - `COLOUR_GUIDANCE`: global colour, pattern, type and fabric guidance appended to every suggestion request.
  - `OCCASION_RULES`, `STYLE_GUIDANCE`, `GENDER_STYLING`, and `COLOUR_GUIDANCE` are combined into the `rules` string by `rulesFor()`.
- `src/data/colors.js`: colour hex map, default and garment-specific colour lists, patterns.
- `src/data/types.js`: type options (Pants/Shoes/Skirt/Women types).
- `src/data/garments.js`: garment lists by occasion/gender (men/women/couple formal).
- `src/data/scoring.js`: fit score and warnings implementation.
